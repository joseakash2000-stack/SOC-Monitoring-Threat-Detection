# SOC L1 Incident & Case Management Workflow

This extension adds a lightweight, portfolio-safe incident/case workflow to the Splunk SOC lab. It models how an L1 analyst moves a detection from alert intake through disposition, escalation, documentation, and closure.

> **Scope:** This is a simulated case-management workflow for a controlled lab. It is not a production ticketing system and does not claim integration with ServiceNow, Jira, or another ITSM platform.

## Analyst Workflow

```text
Splunk Alert
    ↓
Alert Intake
    ↓
Validate Detection
    ↓
True Positive / False Positive Decision
    ↓
Investigate Source / Destination / Context
    ↓
Assign Severity
    ↓
Enrich + MITRE ATT&CK Mapping
    ↓
Create Incident Record
    ↓
Escalate When Criteria Are Met
    ↓
Document Findings / Actions
    ↓
Resolve / Close Case
```

## Alert Disposition

| Disposition | Meaning | Example |
|---|---|---|
| True Positive | Alert represents suspicious or policy-violating activity supported by available evidence | Repeated SSH authentication attack pattern |
| False Positive | Alert is generated by legitimate or expected activity after validation | Authorized scanner triggering a scan signature |
| Benign / Expected | Detection is technically valid but activity is expected and requires no incident response | Approved administrative scanning |
| Needs Investigation | Evidence is insufficient to make a final disposition | Unusual network activity with limited context |

## Minimum Case Record

Every investigated alert should capture:

- Case ID
- Alert timestamp
- Detection/signature
- Source IP
- Destination IP
- Destination port/service
- Initial severity
- True positive / false positive / benign / needs-investigation disposition
- Investigation summary
- MITRE ATT&CK context, when applicable
- Related alerts
- Recommended action
- Escalation decision
- Analyst notes
- Final status

## Escalation Criteria

Escalate when one or more of the following are supported by evidence:

1. Successful authentication follows repeated credential attacks.
2. Evidence suggests successful exploitation or host compromise.
3. Critical or high-severity activity targets an important system and cannot be dismissed as authorized activity.
4. Multiple related alerts indicate a broader attack sequence.
5. The analyst lacks sufficient authority or context to perform containment.

> A detection alone is not proof of compromise. Escalation should be based on the available evidence and the organization's incident-response procedure.

## Case Example — SSH Brute Force

**Case ID:** SOC-2026-001

**Detection:** `SOC DEMO - SSH Brute Force`

**Initial severity:** Critical

**Disposition:** True Positive — simulated attack activity

**MITRE ATT&CK:** T1110 — Brute Force

**Investigation summary:** Repeated SSH connection attempts from the simulated source were reviewed against the destination host and port 22. Related activity was correlated in Splunk. The analyst checks authentication logs for failed and successful logins before deciding whether compromise is suspected.

**Escalation:** Escalate if successful authentication, suspicious post-authentication activity, or other evidence of compromise is identified.

**Recommended action:** Review authentication logs, correlate related activity, document findings, and follow the authorized containment/escalation process if malicious activity is confirmed.

**Final status:** Closed after investigation in the controlled lab.

## Case Example — Authorized Network Scan

**Case ID:** SOC-2026-002

**Detection:** `ET SCAN Possible Nmap User-Agent Observed`

**Initial severity:** Medium

**Disposition:** Benign / Expected when the source is confirmed as the authorized lab scanner.

**MITRE ATT&CK:** T1046 — Network Service Discovery

**Investigation summary:** The analyst validates the source, destination systems, destination ports, and timing. If the source is the authorized Kali lab host performing a planned scan, the detection is retained as a valid detection but does not require escalation.

**Final status:** Closed as expected activity.
